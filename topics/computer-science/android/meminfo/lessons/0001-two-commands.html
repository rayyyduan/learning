第 1 课：两条命令

先分清 dumpsys meminfo 的两种调用。表里的每一行留到下一课。

dumpsys 跑在设备上，把某个系统服务此刻的状态打成文本。内存这份服务叫 meminfo。它给的是某一个时刻的快照，单位是 KB。过去几小时的变化不在这里，那是 procstats 的事。

主资料：dumpsys 的 meminfo 一节。整机视图和 -a / -s 见 Quick assessment tools。

整机，或一个进程

flowchart TD
  A["adb shell dumpsys meminfo"] --> B{"后面有包名或 pid 吗"}
  B -->|没有| C["整机快照：进程按 PSS 排列"]
  B -->|有| D["这一个进程的分配表"]

不写参数：

adb shell dumpsys meminfo

得到整机摘要：总内存、空闲内存，以及按 PSS（proportional set size，按共享比例分摊后的内存）排列的进程列表。

写上包名或进程号：

adb shell dumpsys meminfo com.google.android.apps.maps
adb shell dumpsys meminfo 18227

得到这一个进程的表。开头一行是 ** MEMINFO in pid … [包名] **。同一台机器上，包名和 pid 指向同一份报告。

命令对照表在 meminfo 命令。

先看两列

单进程表有很多列。Android 开发者文档写明：一般先看 Pss Total 和 Private Dirty。

  • Pss Total：这一行里，只属于本进程的页，加上和其他进程共享的页按份额分摊之后的大小。把各进程的 PSS 加起来，接近这些进程实际占用的内存，所以它适合拿来和别的进程、和整机可用内存比。
  • Private Dirty：只属于本进程、而且已经被改过的内存（匿名内存也算在这里）。系统不能把它直接丢掉。本进程结束后，这部分才还给系统。查泄漏时先看它。

TOTAL 那一行的 Pss Total，是上面各行 PSS 的和，也就是这个进程的整体内存重量。

表头会随版本变

dumpsys 页的示例把第四列标成 Swapped Dirty。2026 年的指南把同一位置标成 SwapPss，并多了一列 Rss。读你自己的输出时，以你设备打出来的表头为准。
